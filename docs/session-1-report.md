# Сессия 1 — форк, ребрендинг, CI. Отчёт

**05.10.2026.** Цель сессии: репозиторий tenvpn-client со своим именем собирается в CI под три платформы; тег `v0.1.0` с APK и `.exe`, которые ставятся и работают с подпиской.

Итог: форк FlClash-Patched v0.9.1 переименован в **TENVPN** (`com.tenvpn.app`), ядро вынесено в свой форк [Chebobakov/mihomo](https://github.com/Chebobakov/mihomo) и закреплено тегом `v1.19.32-tenvpn.1`, версия ядра прошивается при сборке. CI собирает подписанный APK на Linux, установщик Windows и iOS без подписи. Подписанный нашим ключом APK поставлен на телефон владельца: подписка добавилась по ссылке `tenvpn://`, системный VPN поднялся, через приложение работают Reality, Hysteria2, gRPC и WebSocket. По дороге нашлась причина, из-за которой подписка вообще не добавлялась, — панель выбирает формат по User-Agent (§6).

## 2. Чистая сборка и «необъяснённая осечка» сессии 0

Чистый клон v0.9.1 до любых правок собрался под обе платформы: Android — 13 мин 49 с (три APK по ABI), Windows — 3 мин 30 с. Но не с первого раза, и все причины теперь названы:

1. **База ушла вперёд.** v0.9.1 требует NDK `30.0.16248370` и compileSdk `37.2` (в сессии 0 было NDK 28 / SDK 36). Gradle пытается доставить их сам, а `sdkmanager` из cmdline-tools 23 на этой машине падает (`NTSTATUS 0xC0000409`, «Package ndk not found») — он перенаправляет в новый CLI с другим синтаксисом. Поставлено вручную: `android.exe sdk install ndk/30.0.16248370 platforms/android-37.2`. Три правки NDK из §10 сессии 0 повторены для NDK 30 скриптом `tool/fix_windows_ndk.sh` (идемпотентный; `libclang.dll` в NDK 30 уже есть, но в `bin/`; 138 обёрток clang заменены жёсткими ссылками).
2. **`tool/geodata.dart` стал библиотекой** — `dart run tool/geodata.dart` падает с «must have a main function». Гео-базы теперь качает `setup.dart` перед сборкой. В README записано: при сборке в обход `setup.dart` базы надо положить самому, иначе ядро не стартует.
3. **Упаковщик `flutter_distributor`** ставится в pub-кеш из git: без `core.longpaths` часть файлов не выписывается (`Method not found: 'AppPackagePublisherFirebaseHosting'`), а без `%LOCALAPPDATA%\Pub\Cache\bin` в PATH `setup.dart` его не находит. Ссылка на форк упаковщика закреплена коммитом `c6966745` вместо плавающей ветки `FlClash`.
4. **«File modified during build. Build must be rerun.»** — это и есть осечка сессии 0. Хук сборки ядра объявляет каталоги вывода (`libclash/android/<abi>`) зависимостями, а сам же пишет в них при первой сборке ABI. Flutter видит изменённую зависимость и перезапускает хук; в этой сессии он сделал это сам, и сборка дошла до конца. Если в это время трогать дерево (у меня это был `git fetch` в подмодуле ядра), сборка падает. Правило в README: не запускать две сборки и не трогать дерево, пока идёт сборка.
5. После переименования бинарника нужен чистый `build/windows`: в кеше CMake остаётся цель `FlClash` («No target FlClash»).

**Осторожно:** `setup.dart` возвращает код 0, даже когда упаковщик упал. В CI после сборки стоит проверка «`dist/` не пуст» и проверка подписи APK.

## 6. Находка: панель выбирает формат подписки по User-Agent

Первая установка не добавила подписку — экран «Профили» остался пустым без всякой ошибки. Причина: Remnawave смотрит на **начало** User-Agent. На `FlClash/…` она отдаёт mihomo-YAML, на `TENVPN/…` — base64-ссылки, которые mihomo-клиент не читает. Проверено напрямую: `mihomo …`, `clash-verge/…`, `clash.meta` → YAML (тот же байт в байт, что получал FlClash); `TENVPN/… clash.meta`, `TENVPN/… mihomo/…` → base64.

Решение в клиенте: UA теперь `mihomo TENVPN/v0.1.0 Platform/android` (`lib/common/package.dart`). Работает с текущей панелью без её правки. Если когда-нибудь захочется видеть в панели «TENVPN» отдельным клиентом — это правило ответа на стороне Remnawave (сессия 4), а не клиента.

Выводы:

1. Всё, кроме xhttp, работает и в ядре, и в приложении, на домашнем провайдере.
2. **AmneziaWG 2.0 ядро форка понимает**: конфиг с диапазонами `H1–H4` и `S3/S4` принят целиком (`mihomo -t`), трафик через пир прошёл и на ПК, и на телефоне. Это закрывает половину вопроса «понимает ли ядро AWG 2.0» — вторая половина (через приложение, AWG-профилем из личной админки) — в сессии 2.
3. **xhttp не работает ни одним путём** — с ПК, с телефона, в ядре и в приложении. Ядро все ключи из подписки (`reuse-settings`, `x-padding-obfs-mode`, `uplink-data-placement`, `session-table` и т. д.) знает — проверено по исходникам. В сессии 0 фронт №1 работал; в инвентаре инфраструктуры его SNI-домен числится за выведенным сервером, фронт №2 мёртв с сессии 0. Это задача инфраструктуры, не клиента.
4. Внешний IP «германской» Reality-ноды геобаза ifconfig.co относит к России (провайдер FIBERSTATE). Сайты с проверкой страны могут видеть пользователей этой ноды как российских — для инфраструктуры.
5. Переключение прокси в приложении **не рвёт уже открытые соединения**: браузер, переиспользуя соединение, показывал старую страну. Для пользователя это выглядит как «переключил, а ничего не поменялось» — в сессии 3 включить закрытие соединений при смене сервера.

## 8. Что не получилось или не делалось — и почему

- **xhttp** — §7, инфраструктура.
- **AWG в приложении** не проверялся: подписка Remnawave AWG не содержит, а подмешивание AWG-профиля из личной админки — это и есть сессия 2. Ядро AWG 2.0 тянет (§7).
- **Windows вживую не проверялся** — по решению владельца проверки сети только на телефоне; ПК к тому же сидит за туннелем AmneziaWG. Windows-сборка собрана локально (zip, внутри `TENVPN.exe`, `TENVPNCore.exe`, `TENVPNHelperService.exe`), установщик `.exe` собирает CI. Проверка установщика на чистой Windows — сессия 5.
- **iOS** — только компиляция без подписи, как и требовал план.
- **WebDAV вырезан из интерфейса, но не из кода**: модель `DAVProps`, клиент `lib/common/dav_client.dart`, диалоги `WebDAVFormDialog`/`RemoteBackupsDialog` остались, потому что на них завязаны миграции настроек и тесты. Без UI настроить WebDAV нельзя, сетевых обращений нет. Добить в сессии 3, где экраны режутся целиком.
- **Импорт подписки молча проваливается**, если пришёл не YAML (§6): ни ошибки, ни подсказки. Для сессии 3.
- **DNS по умолчанию — китайские** (`223.5.5.5` и т. п. в настройках по умолчанию апстрима). Для сессии 2 (слой конфига TENVPN).
- Гео-базы качаются с `MetaCubeX/meta-rules-dat` `latest` — не закреплены по версии, сборка не воспроизводима побитно.
- Языки ja/zh_CN оставлены от апстрима; Linux/macOS-упаковку не трогали (не наши платформы).
